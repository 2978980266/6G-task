# 连续路口记录：身份、动态车辆与直接风险事件

本入口读取根目录 `trajectories_0001.csv`，使用 `DEMO/data/config/intersection.yaml` 和 `DEMO/data/config/risk_pair_events.yaml`。旧的冲突点模式仍为默认配置；新入口显式开启 `pair-events`，不再依赖轨迹聚类。

## 身份与在线输入

有身份字段时，以 `(sessionId, trackId, visitId)` 区分一次进出记录，映射为确定的内部整数 ID，同时保留原始 `vehicleId`。同一辆车再次进入不会继承前次进出的缓存。旧 CSV 保持原来的整数 ID 方式。重复身份行、身份元数据冲突、非有限数值及时间冲突会报错，不会悄悄覆盖。

环境逐帧更新活跃车辆。车辆离开后，其历史信息可以保持陈旧状态，但不能继续充当活跃通信端点；新进入车辆从当前真实观测开始积累历史。模型通过 `DynamicCatalogue` 在首次公开看见身份时分配匿名槽位，单回合内不复用，回合结束清空映射和 RSSM 状态。默认容量为 80，超过容量显式报错，可用 `--capacity` 修改后重新训练；容量覆盖回合内先后出现的身份总数，不只是同时在场数量。

网络仍使用共享节点和车辆对编码：节点 `[capacity,16]`、车辆对 `[capacity,capacity,67]`、合法性掩码 `[capacity,capacity,3]`、全局向量 `[6]`。每个节点的特征长度固定，保留必要的二次车辆对信息；完整动作目录采用延迟枚举。填充槽不生成虚构位置或动作。

## 风险真值与车辆判断

离线标签直接检查不同身份车辆的连续轨迹线段，先通过时间窗口、包围盒和方向筛选，再计算精确交点与插值到达时刻。默认航向夹角为 45–135 度、到达时差不超过 1.5 秒、高度差不超过 3 米；不把平行、对向或高架交叉归为此类交叉风险。该定义不覆盖追尾、全部碰撞类型或控制车辆避撞。

每回合从第 4 步开始，每隔 4 步，对当时在场车辆判断其未来 1.5 秒内是否有上述事件。公开任务只由当前身份与固定日历生成，不公开真实交点、未来出场时间、标签或可评估性。未评分查询也照常执行在线判断。

标签只覆盖记录区域内的事件。有明确 visit 身份时，正常首末出现视为进出记录区域；同一 visit 内缺帧仍为未知。要求主体未来窗口完整、录制时间覆盖前后到达时差所需上下文；时间戳跳过采样间隔的缺口也不允许连接。无法确认的标签不计入风险损失，通信发送费用仍计入目标。标签不声称记录区域外、完全未记录交通参与者的安全性。

车端使用本地感知和实际收到的快照，以历史位移估计速度，进行常速度车辆对交叉预测；没有运动信息时保持未知。世界模型仍在 RSU 辅助调度，不向车辆注入预测对象状态。下行候选保留更新版本的安全预测、风险预测和未知对象，允许消息纠正误报。通信仍是每步最多 2 上行、2 下行、开启中继时 1 中继，端点互斥且下一步可用。

## 数据切分与命令

从项目根目录运行，Python 使用已安装 NumPy、PyTorch 等依赖的环境。本机可将 `python` 替换为 `C:/Users/51412/anaconda3/envs/netllm/python.exe`。

```powershell
python -B DEMO/scripts/intersection_dreamer.py analyze --output-dir DEMO/outputs/intersection_analysis
python -B DEMO/scripts/intersection_dreamer.py train --episodes 2 --size smoke --relay off --capacity 80 --threads 1 --output-dir DEMO/outputs/intersection_train_off
python -B DEMO/scripts/intersection_dreamer.py train --episodes 2 --size smoke --relay on --capacity 80 --threads 1 --output-dir DEMO/outputs/intersection_train_on
python -B DEMO/scripts/intersection_dreamer.py evaluate --model-path DEMO/outputs/intersection_train_on/model.pt
```

输出目录必须不存在。正式规模可省略 `--size smoke`；上述 2 回合仅验证训练、有限损失、合法动作及保存重载。训练结果包含初始化和训练后评估，以及不通信、freshness、车辆对预测三种规则在相同窗口的评估。目标系数沿用原设置；任务定义变化后，原冲突点实验的原始 J 不宜直接比较。

默认按时间分为训练、验证、测试，分区间留 4 帧间隔，分区内采用不重叠的 23 步回合。离线标签上下文只能取自所属分区，不能跨分区读取；回合之外的上下文也不进入在线输入。训练只采样训练分区。

模型输出 `model.pt`、配置元数据、数据报告和指标，不新增 SHA 冻结合同。检查点只支持该新入口，记录容量、结构及场景语义配置，严格加载权重，并自动比较保存前后确定性评估；不包含优化器状态，不用于断点续训。

评估时重新读取元数据中的输入路径；配置校验不检测同一路径下 CSV 内容被替换，因此复现实验需要保留原始输入文件。

## 当前数据规模

当前 CSV 为 37.60 秒、142 帧、5,991 条记录，136 个原始车辆 ID 对应 139 次 visit，每帧约 33–52 辆车。全记录有 39 个符合定义的不同车辆对交叉事件；事件数不同于周期查询正例数。

默认切分得到 3 个训练回合、1 个验证回合、1 个测试回合。可评分查询分别为 524、83、73，正例分别为 24、6、2；另有 376 个不可评估查询。训练与验证/测试分别仍共享 32/14 个 visit，时间切分不等于独立路口、独立场景验证。

这批数据可以验证接入与训练流程，尚不足以支撑稳定性能或泛化结论。应补充更长记录、更多独立 session、不同流量和路口，并增加独立测试集风险事件。当前沿用已有建筑数据和 RSU 坐标；若新 CSV 来自修改后的地图，需要替换对应几何与部署配置。
